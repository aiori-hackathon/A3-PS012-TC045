9. Method: the four rules

Each server receives one baseline query (RD off, a name in its own zone) and 3 canary queries (RD on, a fresh unique name each time, in a zone served only by our canary server). The canary server logs every query it receives. Rules are checked in order and the first match decides:

RuleVerdictCondition
1RecursiveEvery canary attempt is NOERROR with RA set, the marker answer, and a hit in the canary log
2RefusedThe baseline and every canary attempt are REFUSED
3Authoritative-onlyThe baseline is answered with AA; every canary attempt gets a reply with no answer, no RA and no canary hit
4InconclusiveAnything else, with a reason: TIMEOUT, SERVFAIL, TC_FAIL, CONFLICT, ERROR or NO_DATA

10. Comparison with single-flag checks

The same evidence judged by simpler rules, on one question: does the server provide recursion to the external client? A single-flag check reads only the first RD=1 reply. That is not enough when a server can set RA and return an answer without ever recursing (a sinkhole, a DNS firewall, a local-data override). ResolverLens also requires the canary server's log to show the lookup.
